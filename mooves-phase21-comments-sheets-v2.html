The one spec change this needs

The approved spec says "no comment count anywhere, for anyone." That sentence was a side effect of the single-arrow merge, not one of the four walls. The wall is narrower and still holds here: a non joiner sees no count and no hint. A total shown to someone already in reads the same whether they have opened it ten times or never, so it is not an unread badge and cannot nag. If you approve this, that line in the spec gets amended to "no comment count is shown to anyone who has not joined, and no count anywhere tracks what you have read."

Where this deliberately parts from Venmo

No count for non joiners, which is the whole of wall 3 and the one thing Venmo cannot teach us.

No heart and no emoji reactions. Venmo's row has three buttons; ours has two targets because reactions were cut in Phase 20 and are out of scope here. A lone bubble on its own row looked thin, which is why the roster shares the line.

Venmo's feed is the product. Ours is a departure lounge, so the sheet restates the Moove and offers a way out to the group text rather than inviting a scroll.

What it costs to switch

The migration and all four API routes are untouched — the data model was right either way. `PlanComments` moves out of `WhosIn`'s footer into a sheet with two panes, `WhosIn` reverts to how it shipped, and the card row is rebuilt. One new thing the API does need: a comment count per Moove in the feed payload, joiner only, which today it does not return because we had decided never to show one.
